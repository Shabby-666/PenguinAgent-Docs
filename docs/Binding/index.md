# 绑定系统

绑定系统把 QQ 账号与 Minecraft 玩家名关联起来，用于：

- 查背包 / 末影箱（`/我的背包`、`/我的末影箱`）
- 双向昵称显示（群聊发消息时显示游戏 ID 或 QQ 昵称）
- 游戏内 `/at` 命令发送 QQ @提醒
- 自定义命令中的 `{name}` 与 `{nickname}` 占位符
- 配合白名单做准入控制

## 绑定以 openid 为准，跨群通用

绑定关系用 **openid**（不是 QQ 号、也不是昵称）作为唯一标识。这意味着：

- 同一个群绑定成功后，**该服务器的所有群都视为已绑定**，查背包不用再绑一次
- 换 QQ 昵称不影响绑定
- MC 玩家名同样**全局唯一**，避免不同群各绑一个同名角色导致冒名顶替

## 绑定流程

### 游戏验证绑定（默认）

`binding.require-game-verification` 默认为 `true`：

1. 在 QQ 群发送 `/绑定 <游戏ID>`
2. 系统生成 5 位验证码
3. 玩家用该角色进入服务器，执行 `/qqbind <验证码>`
4. 验证通过后完成绑定

```
玩家：/绑定 Steve
HuHoBot：请使用角色 Steve 进入服务器执行 /qqbind 48132
HuHoBot：验证码 5 分钟内有效
```

游戏内：

```
/qqbind 48132
HuHoBot：已绑定 QQ 账号到 Steve
```

### 直接绑定

`binding.require-game-verification` 设为 `false` 时，`/绑定 <游戏ID>` 直接完成绑定，无需进服验证。

!!! warning

    绑定命令执行后是否要过游戏内验证由该开关决定，但**强制绑定开启时这条配置不生效**。

### 强制绑定

开启后，未绑定的玩家**一进服务器就会被踢出**，并拿到一个 5 位验证码；在 QQ 群执行 `/绑定 <验证码>` 完成绑定，重新进服即可游玩。

```yaml
binding:
  force-bind: true
  force-bind-groups:
    - "123456789"
    - "987654321"
```

踢出画面里带全部信息：服务器名、说明、验证码、群号与命令、重新进入会刷新验证码的提示。

流程：

1. 玩家进服 → 立刻被踢出，拿到验证码 `48132`
2. 在指定 QQ 群执行 `/绑定 48132`
3. 绑定成功，重新进服即可正常游玩
4. **解绑后玩家下次进服同样被踢出**；若该玩家当前在线，其连接会被立即断开

验证码 5 分钟内有效，**每次重新进入服务器都会刷新**（旧验证码立即作废）。

!!! warning

    **开启前务必确认**

    - **不要安装任何白名单插件，也不要开启 Minecraft 自带白名单**。否则未绑定玩家会在白名单阶段先被拦下，根本拿不到验证码。
    - 强制绑定依赖 QQ 机器人可用。若 QQ 未连接，插件会自动把 `binding.force-bind` 改回 `false` 并在日志说明，避免把人挡在门外却绑不了。
    - 强制绑定开启时，绑定与解绑**不再执行**白名单同步命令。

### 管理员强制解绑

用于撤销冒名顶替的绑定（如关闭游戏内验证时，有人恶意绑定他人角色）。

```
/强制解绑 <MC玩家名 | @某人 | openid | QQ昵称>
```

仅管理员可用。目标支持多种写法，`@某人` 可直接从群消息里提及。会同步移出白名单（强制绑定开启时跳过白名单操作，只踢人）。

## 解除绑定

在 QQ 群发送 `/解除绑定`，会先发一个确认键盘：

```
HuHoBot：确认解除绑定？
         绑定角色：Steve
         解除后会同步移出白名单，30 秒内未选择视为取消。
         [ 确定 ]  [ 取消 ]
```

- 点「确定」→ 撤回键盘消息 → 解绑 → 同步移出白名单
- 点「取消」或 30 秒超时 → 撤回键盘消息，**不解绑**
- 只有发起者本人能操作该按钮

## 显示名称设置

绑定后可以分别控制两个方向显示的名称。

### QQ→游戏方向

| 命令 | 效果 |
|------|------|
| `/MC显示名称 MC` | 显示游戏 ID（如 `Steve`） |
| `/MC显示名称 QQ` | 显示 QQ 昵称 |

### 游戏→QQ 方向

| 命令 | 效果 |
|------|------|
| `/QQ显示名称 MC` | 显示游戏 ID |
| `/QQ显示名称 QQ` | 显示 QQ 昵称 |

切换后对**所有群**同时生效。

## 游戏内命令

### /qqbind

```
/qqbind <验证码>
```

验证码来自 QQ 群 `/绑定` 命令，5 分钟内有效。强制绑定流程下不需要这一步。

### /at

```
/at <群成员昵称> <消息内容>
```

- 支持 Tab 键昵称补全
- 昵称对应有效 OpenID 时会发送真正的 @提醒
- 消息格式：`<@openid> 消息内容`

## 配置

```yaml
binding:
  # 是否需要游戏内 /qqbind 验证；强制绑定启用时本条配置无效
  require-game-verification: true
  # 强制绑定；QQ 未连接时会自动关闭
  force-bind: false
  # 提示里展示的 QQ 群号，可填多个；留空则不提示具体群号
  force-bind-groups: []
```

三项都可在 WebUI「绑定」页配置。

## 白名单同步

绑定/解绑时自动执行白名单命令：

```yaml
whitelist:
  add-command: "whitelist add {name}"
  del-command: "whitelist remove {name}"
```

`{name}` 会被替换为玩家名。留空则不同步；**强制绑定开启时这两条不执行**。

## 存储位置与迁移

绑定数据保存在插件数据目录的 `command-state.ini`：

```ini
[user-bindings]
# openid = MC玩家名:QQ显示名模式:MC显示名模式:QQ昵称
A336102D3919B498DAEC91A821517B41 = _Chinese_Player_:QQ:QQ:某只神兽
```

早期版本按群分组存储（`[bindings]` / `[binding-settings]` 段）。升级到 1.16.0 时会自动迁移为按 openid 索引，跨群重复的记录会合并并保留原有的显示名称设置，**无需手动改文件**。

## 注意事项

- 一个 openid 只能绑定一个角色；MC 玩家名全局唯一
- 解绑后该角色可以被其他用户绑定
- 建议开启游戏内验证（默认），避免他人冒用你的角色名
- 绑定数据存放在本地文件，重启不会丢失；删除该文件即清空全部绑定
