# 服务器状态通知

服务器**正常关闭、重启完成、意外关闭**时，自动往 QQ 群发一条提醒，不用再盯着控制台。功能从 v1.20.0 开始提供，目前仅 Spigot / Paper 平台实现。

## 配置

```yaml
server-notify:
  # 总开关，关闭后下面三项都不发送
  enabled: true

  shutdown:
    enabled: true
    # 可用占位符：{server}、{platform}
    message: "服务器已正常关闭"

  restart:
    enabled: true
    message: "服务器已重启完成"

  crash:
    enabled: true
    # 上次运行没有正常关闭（崩溃、kill -9、断电等）时，下次启动后发送
    message: "服务器意外关闭（崩溃或被强制结束），请管理员检查控制台"

  # 上次正常关闭后多少秒内重新启动算作重启，建议 120-300
  restart-window: 180
```

配置版本为 12，升级后启动时会自动补上这组默认值，不需要手动改 `config.yml`。所有项都能在 WebUI 的「服务器状态通知」分区里图形化编辑。

## 发送时机

| 通知 | 触发时机 | 说明 |
|---|---|---|
| 关机 | 服务器停止的**瞬间**立即发送 | 在 `onDisable` 里抢在 QQ 连接关闭之前发出 |
| 重启完成 | **下次启动**时判定后发送 | 上次正常关闭，且距停止时间不超过 `restart-window` |
| 意外关闭 | **下次启动**时补发 | 上次没有正常收尾（崩溃、`kill -9`、断电） |

### 为什么重启和崩溃要等到下次启动

在插件的视角下，「关服」和「重启」是同一件事 —— 都是先 `onDisable`，再由新进程 `onEnable`。区别只存在于「多久之后又起来了」这一点上，所以只能在下次启动时回头看：

```text
上次 onDisable  ──写入 clean=true + stop-time──►  下次 onEnable
                                                    ├─ 距 stop-time ≤ restart-window → 重启
                                                    └─ 超出窗口 → 普通开机，不发送

上次 onEnable 写了 clean=false，之后进程直接消失 ──►  下次 onEnable → 崩溃
```

崩溃通知尤其如此：进程已经死了，唯一的发送机会就是下一次启动。如果服务器崩了之后没人再启动它，这条通知不会发出 —— 这是当前实现的边界，不是 bug。

### 插件重载不会被误判

`/reload` 或手动停用插件时，服务器其实还在跑：

- 不会发送关机通知（日志里会写「检测到插件重载或手动停用，跳过关机通知」）
- 不会记录停止时间，因此不会被下次启动误判成一次重启
- 仍会记录一次「正常收尾」，避免「先手动停用插件、再正常关服」被误报成崩溃

## 跨进程状态文件

判定依赖插件数据目录下的 `server-notify-state.properties`：

```properties
jvm-start=1761897600000     # 写入时的 JVM 启动时间，用来识别插件重载
stop-time=1761898200000     # 真实关服时刻；插件重载时写 0
clean=true                  # 上次是否正常收尾
```

- 每次 `onEnable` 写入 `clean=false`，表示「这次运行还没收尾」
- `onDisable` 写入 `clean=true`
- **不要手动删除这个文件**：删掉后下一次启动会按「普通开机」处理，崩溃/重启通知会漏发一次

## 发送细节

- 发给 `bot.groups` 里的**每一个群**；未配置群时记日志跳过
- QQ 是异步鉴权的，通知会等鉴权成功后再发，最长等 **60 秒**（2 秒一次，最多 30 次）
- 鉴权成功但发送失败会重试 **3 次**，仍失败则在控制台写警告
- 关机通知是同步发送的，网络很差时会略微拖慢关服流程

## 排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 关服没收到通知 | `server-notify.enabled` 或 `shutdown.enabled` 关闭 | 打开对应开关 |
| | `message` 为空 | 填回消息文本 |
| | `bot.groups` 为空 | 用 `/查信息` 取群 OpenID 填入 |
| | 是插件重载而不是关服 | 正常，不会发 |
| | QQ 未鉴权成功 | 检查 `app-id` / `secret` 与控制台登录日志 |
| 重启没收到通知 | `restart-window` 太小，服务器启动慢 | 调到 300 或更大 |
| | 上次其实是崩溃而不是正常关闭 | 会发崩溃通知，不发重启通知 |
| | 上次是插件重载 | 正常，重载不记停止时间 |
| 崩溃通知误报 | 上次是 `kill -9`、断电、OOM 被杀 | 这就是意外关闭，属正常提示 |
| | 上次手动删过插件目录 | 状态文件丢失，会按普通开机处理 |
| 通知发到了错误的群 | `bot.groups` 里有多余群 | 清理 `groups` 列表，或按群屏蔽 |

## 相关配置

- `bot.groups`：通知发送目标群，见[快速开始](../QuickStart/index.md#bot-基础信息与群聊绑定)
- `serverName`：对应消息里的 `{server}` 占位符
- 状态通知只解析 `{server}` 与 `{platform}` 两个占位符，不走 PlaceholderAPI
